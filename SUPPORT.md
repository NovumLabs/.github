# Support

## Welcome to Novum Labs

Thank you for using, exploring, or contributing to Novum Labs projects.

We aim to build useful AI technologies, language-model experiments, developer tools, and reliable software through research, engineering, and open-source collaboration.

This document explains how to get help with our projects and how to direct questions to the appropriate place.

## Getting Help

### 1. Questions About a Project

For questions about installation, configuration, usage, or project functionality:

- Read the project's `README.md`.
- Check its documentation and examples.
- Review existing GitHub issues and discussions, if enabled.
- Open a new question or discussion in the relevant repository when appropriate.

Please include the repository name and enough technical context to help others understand your question.

### 2. Reporting a Bug

If you believe you have found a bug:

- Search existing issues to check whether it has already been reported.
- Open an issue in the affected repository.
- Describe what you expected to happen and what actually happened.
- Include steps to reproduce the problem.
- Provide relevant error messages, logs, software versions, and environment details.

Please remove API keys, passwords, personal information, and other sensitive data before sharing logs or screenshots.

### 3. Suggesting a Feature

We welcome thoughtful suggestions that improve usability, reliability, accessibility, research quality, or developer experience.

When proposing a feature, explain:

- The problem you are trying to solve.
- The proposed improvement.
- Who would benefit and how.
- Any alternatives or implementation ideas you have considered.

Submit the suggestion through the relevant repository's issue tracker or discussion area, where available.

### 4. Contributing to a Project

Contributions from developers, researchers, students, educators, and other interested community members are welcome.

Before submitting a contribution:

- Read the repository's `CONTRIBUTING.md`, if available.
- Check the project's license and contribution requirements.
- Review existing issues and pull requests.
- Follow the project's coding, testing, and documentation practices.

For organization-wide guidance, see the `CONTRIBUTING.md` file in the Novum Labs `.github` repository.

### 5. Security Concerns

**Please do not report security vulnerabilities through public GitHub issues or discussions.**

Follow the instructions in the affected repository's `SECURITY.md` file. Where available, use GitHub's private vulnerability reporting feature.

Please report suspected vulnerabilities responsibly and avoid sharing credentials, confidential information, or personal data publicly.
